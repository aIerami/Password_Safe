# Сейф паролей: как получить APK

Менеджер паролей только для вашего телефона. Ничего не отправляется в интернет (у приложения нет такого разрешения). APK собирается бесплатно на серверах GitHub, ставить ничего на компьютер не нужно.

**Важно:** репозиторий делайте **Private** (закрытым). В нём будет лежать ключ подписи вашего приложения.

## Шаг 1. Аккаунт GitHub
Откройте github.com, нажмите Sign up, введите почту, пароль, имя пользователя, подтвердите почту кодом из письма. Если аккаунт уже есть, просто войдите.

## Шаг 2. Новый закрытый репозиторий
1. Справа вверху «+», затем New repository.
2. Repository name: `sejf-paroley`.
3. Выберите **Private**. Галочки README, .gitignore, license не ставьте.
4. Create repository.

## Шаг 3. Загрузка проекта через git (один раз)
Проект уже оформлен как git-репозиторий (в архиве есть скрытая папка `.git`), поэтому загружать файлы через сайт не нужно.

1. Установите **GitHub Desktop** (бесплатно, desktop.github.com) и войдите в свой аккаунт.
2. Распакуйте `SejfParoley-project.zip` в удобную папку, например `Документы\SejfParoley-project`.
3. В GitHub Desktop: File, **Add local repository**, выберите эту папку, Add repository.
4. Нажмите **Publish repository**. Название `sejf-paroley`, **поставьте галочку «Keep this code private»**, Publish repository.

Готово: код на GitHub, папка `.github` на месте. Если GitHub Desktop не ставится: установите Git (git-scm.com) и дважды щёлкните файл `Отправить-на-GitHub.bat`, а для самого первого раза выполните в папке команды из раздела «Без GitHub Desktop» ниже.

## Шаг 4. Постоянный ключ подписи (делается один раз)
Зачем: Android ставит обновление поверх старой версии только если у обоих одна и та же подпись. Без постоянного ключа каждую новую версию пришлось бы ставить, удалив старую вместе со всеми паролями. С постоянным ключом обновляется без потери данных.

1. Вкладка **Actions**. Если GitHub просит разрешить, нажмите зелёную кнопку «I understand my workflows, go ahead and enable them».
2. Слева выберите **Создать ключ подписи (один раз)**, справа Run workflow, зелёная кнопка Run workflow.
3. Через 1–2 минуты появится зелёная галочка. Нажмите на этот запуск, внизу в разделе Artifacts скачайте `signing-secrets`, распакуйте, откройте `signing-secrets.txt` блокнотом. В нём три блока: `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, под каждым значение.
4. В репозитории: Settings, слева Secrets and variables, Actions, кнопка **New repository secret**. Создайте три секрета:
   - Name: `KEYSTORE_BASE64`, Secret: длинная строка из блока KEYSTORE_BASE64 (копируйте целиком, без пробелов и переносов);
   - Name: `KEYSTORE_PASSWORD`, Secret: значение из блока KEYSTORE_PASSWORD;
   - Name: `KEY_ALIAS`, Secret: `sejf`.
5. **Сохраните `signing-secrets.txt` в надёжном месте** (например, в облаке или на флешке) и потом удалите артефакт: Actions, запуск, рядом с `signing-secrets` значок корзины. Если ключ потеряется и секреты пропадут, новые версии нельзя будет поставить поверх старой. Тогда выручит резервная копия паролей.

## Шаг 5. Сборка APK
1. Actions, слева **Собрать APK**, Run workflow, зелёная кнопка.
2. Подождите 5–10 минут: жёлтый кружок значит «идёт», зелёная галочка «готово».
3. Откройте завершённый запуск. В логе шага «Проверка готового APK» должно быть видно, что разрешения INTERNET нет, и отпечаток подписи SHA-256. Этот отпечаток должен быть одинаковым во всех будущих сборках.
4. Внизу страницы, раздел Artifacts: скачайте `Sejf-Paroley-APK`, распакуйте, внутри `app-release.apk`.

## Шаг 6. Установка на телефон
1. Передайте `app-release.apk` на телефон (Telegram «как файл», почта, облако, кабель).
2. Откройте файл. Android попросит разрешить установку из этого источника: разрешите.
3. Если Play Protect пишет про неизвестного разработчика, выберите «Всё равно установить».
4. Приложение называется «Сейф паролей». При первом запуске придумайте мастер-пароль (запишите на бумаге) и сразу сделайте резервную копию (Ещё, Резервная копия).

## Как обновлять приложение без потери паролей
1. В приложении: Ещё, Резервная копия, Сохранить копию (на всякий случай).
2. Замените файлы проекта новыми (например, распакуйте обновлённый архив поверх папки проекта с заменой). Папку `.git` не трогайте.
3. Откройте GitHub Desktop: слева появится список изменённых файлов. Внизу слева напишите коротко, что изменилось (например, «Категории»), нажмите **Commit to main**, затем **Push origin** вверху. Либо просто дважды щёлкните `Отправить-на-GitHub.bat`.
4. На GitHub: Actions, **Собрать APK**, Run workflow. Через 5–10 минут скачайте новый APK.
5. Установите его **поверх** старого, ничего не удаляя. Пароли останутся, потому что подпись та же, а номер версии у каждой сборки больше предыдущего.
6. Если Android пишет «конфликт» или «приложение не установлено»: НЕ удаляйте старое приложение, пока не убедитесь, что копия сохранена и открывается.

## Без GitHub Desktop (командная строка)
В папке проекта (Git должен быть установлен):
```
git remote add origin https://github.com/ВАШ_ЛОГИН/sejf-paroley.git
git push -u origin main
```
Репозиторий `sejf-paroley` предварительно создайте на github.com (Private, без README). Дальше обновления отправляются файлом `Отправить-на-GitHub.bat`.

## Что делать, если...
- **Красный крестик в Actions**: откройте запуск, нажмите на красный шаг, скопируйте последние 30 строк лога.
- **Ошибка «Не заданы секреты»**: не выполнен шаг 4 или имена секретов написаны не так (регистр важен).
- **Забыли мастер-пароль**: восстановить нельзя. Остаётся «Забыли пароль?», стереть сейф и загрузить копию, но понадобится пароль, действовавший при создании копии.
- **Потеряли телефон**: данные зашифрованы, но сразу смените важные пароли с другого устройства, а на новом телефоне восстановите сейф из копии.

## Проверка кода
В папке `tests` лежат автотесты шифрования (`node tests/crypto.test.js`) и интерфейса (`tests/ui.test.js`, `tests/cats.test.js`, нужен Playwright). Для сборки APK они не нужны.
